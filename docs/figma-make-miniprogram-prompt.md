# LetMeFit 微信小程序 Figma Make 提示词

## 结论

用户初次注册/登录后建议进入引导页。

原因：LetMeFit 的核心体验依赖用户基础档案。年龄、性别、身高、当前体重、活动水平和主要目标会影响体重管理建议、每日总结、记录上下文和 Agent 个性化反馈。

引导页不要做成长问卷。推荐 3 步、1 分钟内完成，并允许“稍后完善”。如果用户跳过，首页顶部持续提示“完善基础档案以获得更准确建议”。

## 使用素材

请在 Figma Make 中上传以下 3 张图片，并在提示词中按名称引用：

- `female-fit-agent.png`：女性 AI 健身 Agent 形象，用于欢迎页、Agent 对话头像、空状态或鼓励状态。
- `male-fit-agent.png`：男性 AI 健身 Agent 形象，用于可选 Agent 头像、切换形象、对话页空状态或双 Agent 展示。
- `fit-chat-background.png`：浅色科技健身背景图，用于 Agent 对话页背景、首页顶部氛围区或 onboarding 背景。使用时要降低透明度或加白色遮罩，保证文字和卡片可读。

## 可直接粘贴给 Figma Make 的提示词

```text
请为 LetMeFit 设计一套微信小程序端高保真 UI。LetMeFit 是一个健康健身管理 Agent，不是医疗应用，不提供诊断、治疗、疾病饮食管理或极端节食建议。

目标用户是 20-40 岁一般健康成年人，主要目标是减脂、体重管理、记录饮食和建立健康习惯。产品核心闭环是：短信登录 -> 首次引导创建基础档案 -> 首页查看今日状态 -> 通过文字/拍照/语音与 Agent 记录饮食或身体指标 -> AI 生成待确认卡片 -> 用户确认或修改 -> 写入正式记录 -> 查看每日总结与建议。

请基于微信小程序移动端设计，画幅按 375px 宽度设计。整体风格简洁、轻量、可信、现代，适合日常高频记录。不要做复杂营销首页，不要做医疗风格，不要做大屏仪表盘。界面应该像一个亲切、可靠、可持续使用的健康记录助手。

请使用我上传的三张素材：
1. 使用 female-fit-agent.png 作为默认 AI Agent 形象，可出现在首次欢迎、Agent 对话头像、空状态、鼓励状态中。
2. 使用 male-fit-agent.png 作为可选 AI Agent 形象，可用于头像切换、双 Agent 展示、或者“选择你的 Agent”页面。
3. 使用 fit-chat-background.png 作为 Agent 对话页背景和部分顶部氛围背景。背景必须低透明度或覆盖白色蒙层，不要影响文字、按钮和确认卡片阅读。

请生成以下核心页面和状态：

1. 短信登录页
- 顶部展示 LetMeFit 品牌名。
- 使用 female-fit-agent.png 或 male-fit-agent.png 做轻量欢迎形象，但不要占满页面。
- 手机号输入框。
- 获取验证码按钮。
- 验证码输入框。
- 登录按钮。
- 简短隐私说明：仅用于健康健身记录与建议。
- 页面要轻量，不要像营销落地页。

2. 首次引导 Onboarding
登录后如果用户还没有档案，进入引导流程。引导流程控制在 3 步，用户应感觉 1 分钟内可以完成。

第 1 步：选择主要目标
- 减脂
- 增肌
- 维持健康
- 建立记录习惯

第 2 步：填写基础身体信息
- 性别：男、女、其他、不透露
- 年龄
- 身高 cm
- 当前体重 kg
- 目标体重 kg，可选

第 3 步：选择活动水平
- 久坐
- 轻度活动
- 中等活动
- 经常运动
- 高强度运动

底部有“下一步”“完成”主按钮。允许“稍后完善”，但要弱化，不要比主按钮显眼。不要询问疾病、用药、孕期、未成年人等医疗或高风险信息。

3. 首页 Home
首页优先回答“我今天状态如何”。
需要包含：
- 顶部问候语和今日日期。
- 今日状态卡片：餐食数量、身体指标、估算热量、蛋白质。
- 明显的快速记录区：记录饮食、记录体重、问问 Agent。
- 如果档案未完成，顶部显示“完善基础档案以获得更准确建议”的提示卡。
- 今日建议卡片，建议文案要简短具体。
- 最近记录列表。
- 可使用 fit-chat-background.png 的浅色局部元素作为顶部氛围，但内容区域必须清晰。

4. Agent 对话页
这是核心页面。使用 fit-chat-background.png 作为浅色背景，并叠加白色/半透明层，保证消息和卡片可读。

消息区包含：
- 用户消息气泡。
- Agent 回复气泡。
- Agent 头像使用 female-fit-agent.png，可在设置中切换 male-fit-agent.png。
- AI 识别后的 Review/Edit 待确认卡片。

底部输入区包含：
- 文本输入。
- 拍照按钮。
- 图片上传按钮。
- 语音按钮。
- 发送按钮。

交互原则：
- 用户可以用文字、图片、拍照、语音和 Agent 交流。
- Agent 能力边界只覆盖健身管理、饮食记录、身体指标记录、每日总结和一般生活方式建议。
- AI 结果不能直接保存，必须进入待确认卡片。

5. Review/Edit 确认卡片
确认卡片是所有 AI 结果写入正式记录前的必经步骤，视觉层级要比普通聊天气泡更强。

请设计两类卡片：

A. 餐食记录确认卡
- 餐别：早餐、午餐、晚餐、加餐。
- 食物列表。
- 每个食物展示：名称、份量、热量估算、蛋白质、碳水、脂肪。
- 低置信度字段用轻提示标识。
- 按钮：修改、确认保存、放弃。
- 卡片文案体现“请确认后保存”。

B. 身体指标确认卡
- 体重 kg。
- 体脂率，可选。
- BMI，可选。
- 记录时间。
- 按钮：修改、确认保存、放弃。
- 视觉上要让用户知道这是候选结果，不是已经保存的正式记录。

6. 每日总结页
展示：
- 今日记录概览。
- 餐食总结。
- 身体指标总结。
- 一段简短建议。
- 记录完整度。
- “继续记录”按钮。

建议文案要轻量，例如：
- “今天蛋白质记录较完整，晚餐可以继续保持清淡。”
- “今天还没有体重记录，可以补充一次身体指标。”

7. 我的/档案页
展示和编辑基础档案：
- 年龄。
- 性别。
- 身高。
- 当前体重。
- 目标体重。
- 活动水平。
- 主要目标。
- Agent 形象选择：女性 Agent / 男性 Agent。
- 退出登录。

底部导航：
- 今日
- 记录
- Agent
- 我的

视觉设计要求：
- 主色以清爽蓝绿色或绿色为主，结合素材中的蓝色科技感和少量橙色点缀。
- 不要让整套 UI 只有一种颜色。
- 卡片圆角约 8px。
- 按钮层级明确：主按钮、次按钮、危险/放弃按钮。
- 文案要短，不要写大段说明。
- 避免医疗感，不要出现医院、医生、诊断、疾病治疗等视觉元素。
- 强调“记录、确认、总结、建议”的闭环。
- 页面要适合真实微信小程序开发落地，不要只做概念稿。
- 请输出完整页面流、主要组件状态、空状态、错误状态和确认卡片状态。
```
